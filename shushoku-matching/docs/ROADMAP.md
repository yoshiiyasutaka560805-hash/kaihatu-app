# 求職者マッチング 理想形ロードマップ

3つのサブエージェントの報告を統合したもの（2026-10-13時点）。

| 担当 | 主な指摘 |
|---|---|
| 法令・コンプライアンス | 3管理簿、事業報告、6か月以内離職の追跡、オンライン提供、AI送信の整理 |
| 業務フロー・UX | 事業所管理の欠落、今日のタスク、AIによる入力削減、提案書 |
| 技術・セキュリティ | 認証なし・CSRF・XSS、帳簿の消失、日付の不具合 |

「要確認」と書いた項目は、一次資料（e-Gov・労働局）を直接読めていない。実装の前に確認する。

## 0. 計画の前提となる3つの判断

1. **ハローワーク求人は「探す材料」。売上になるのは「自社が受け付けた求人」。**
   - 手数料をもらうには、事業所から求人の申込みを受け、手数料と返戻金について合意する必要がある。
   - 実務上は、ハローワーク求人を見つけたら事業所へ連絡し、自社の求人として受け付ける流れになる。正確な法的整理は管轄の労働局に確認する。
   - このため「事業所・自社受理求人の管理」を最優先にする。
2. **求人データの入手は、労働局の「求人情報オンライン提供」（CSVダウンロード）に一本化する。自動巡回は廃止する。**
   - 提供されるのは、事業主が提供に同意した求人だけ。
   - 利用規約で、紹介以外の目的での利用、第三者への提供、一般公開が禁止されている。
3. **法定の帳簿と報告をアプリの中心に置く。**
   - 対象は、求人・求職・手数料の3管理簿（保存期間は2年。要確認）と、毎年4月の事業報告。
   - 事業報告には「無期雇用で就職した人のうち、6か月以内に離職した人数」が必要。
   - これを集めるため、紹介の記録をすべて履歴として残す。

## Phase 1：業務の骨格と法定帳簿（M、1〜2か月）

| 機能 | 内容 | 根拠 |
|---|---|---|
| 事業所・自社受理求人 | 事業所の基本情報（担当者・手数料率・契約日・返戻金規定）。ハローワーク求人から自社求人に変換。労働条件の明示項目（就業場所・業務の「変更の範囲」を含む）の入力漏れチェック | 法令＋業務 |
| 選考の流れと履歴 | 提案→応募→面接（日時・結果）→内定→入職を、日付つきで記録。辞退理由を選択式にする。操作した人を記録する | 業務 |
| 3管理簿の出力 | 求人・求職・手数料の管理簿をCSV/PDFで出力。無期・有期の区分、保存期限の自動計算 | 施行規則24条の7（要確認） |
| 手数料・請求・返戻金 | 届け出た手数料表から請求額を計算し、上限を超えたら警告。入金状況、返戻金の対象期間を自動判定 | 法令 |
| 今日のタスク（ホーム画面） | 面接の前日、入職後1週・1か月・3か月・6か月の確認、在留期限、紹介期限、ビザ更新 | 業務（兼務の代表でも漏れを防ぐ） |
| 地名をコードで照合 | 全国地方公共団体コードで正規化し、必ず都道府県とセットで照合する（「府中市」「北区」の取り違え対策） | ロジック |
| 情報の揃い具合の表示 | 情報不足の求人が高く見えないよう、スコアとは別に情報の揃い具合を表示する | ロジック |
| 求人情報オンライン提供の取込 | 公開されている項目一覧に合わせて取込項目を決め、取得元・取得日・提供条件を記録。外部へ出力できないようにする | 利用規約 |

## Phase 2：入力負担の削減とスマホ対応（M〜L）

| 機能 | 内容 |
|---|---|
| 面談メモ・音声からの条件抽出（AI） | 氏名などを伏せてから送信し、結果は下書きとして担当者が承認してから反映 |
| 提案書（比較表）の自動生成 | 上位3〜5件の求人を比較。PDFとLINE用の文面。多言語（やさしい日本語、英語、ベトナム語ほか） |
| 新着求人の自動照合 | 取込のたびに受付中の求職者と照合し、点数の高い新着求人を通知 |
| 事業報告・情報公開用の集計 | 就職者数、無期雇用の人数、6か月以内の離職、平均手数料率 |
| 苦情受付簿 | 法定の苦情対応の記録 |
| 収集してはいけない情報の検知 | 本籍・思想信条などが入力されたら警告（職業安定法の指針。要確認） |
| 2年間の転職勧奨禁止の警告 | 自社の紹介で就職した人を再び紹介しようとしたら警告 |
| スマホ公開 | Cloudflare Tunnel と Cloudflare Access（Google/Microsoft アカウント＋多要素認証）。個人ごとのアカウント、権限管理、閲覧ログ |
| AI利用の管理 | AI依頼ごとの記録（モデル・トークン数・費用・送信項目・実行者）と月額予算の上限 |

## Phase 3：精度の向上と特定技能への対応（L）

- 介護向けの分類（施設の種類×職種）。特定技能では訪問系の可否も考慮する。
- 夜勤を回数で段階化する。
- 年収見込み（手当・賞与・処遇改善加算を含む）。
- 通勤時間による判定。外部に送る住所は駅または町丁目までに抑える。
- 特定技能の在留管理：在留カードの確認記録、試験の合格状況、在留期限。2027年からの育成就労制度にも備える。
- 求人票のPDF・画像の読み取り（AI）、求職者が事前に入力する多言語フォーム。
- 「何が変われば点数が上がるか」の表示、求職者ごとの重み付け（賃金重視・近さ重視など）。
- 成約実績からの重みの学習は、件数が貯まってから検討する（優先度C）。
